### 0-1. [결정 필요] pet-app 로컬/원격 이력 분기 — 자동 병합 보류함

- **증상**: pet-app만 로컬에 16개의 미푸시 커밋(AppDelegate.swift를 여러 extension 파일로 쪼갠 리팩터링)이 있고, 동시에 원격에는 로컬에 없는 5개 커밋이 있습니다. 그런데 원격 쪽 5개 커밋 중 하나가 **`Shaydi`→`Puck`, `ShaydiTests`→`PuckTests` 전면 리네임(366개 파일)**입니다. 로컬 16개 커밋은 정확히 그 옛 경로(`Shaydi/App/AppDelegate.swift` 등) 안에서 파일을 쪼갠 것이라, 그대로 `git pull`(merge)을 실행하면 파일 rename과 content 변경이 충돌할 가능성이 매우 높습니다.
- **왜 문제인지**: 이건 자동으로 처리하면 위험한 충돌이라 판단해 pull을 실행하지 않고 그대로 두었습니다. 지금 로컬 워킹트리는 여전히 100% `Shaydi` 네이밍입니다 (즉, `Puck` 리네임은 로컬에 전혀 반영 안 됨).
- **선택지**:
    1. 로컬 16개 커밋을 먼저 GitHub에 push한 뒤, PR/리뷰로 리네임과 함께 정리
    2. 원격을 먼저 받고(리네임 포함), 로컬 16개 커밋을 리네임된 경로 기준으로 다시 적용(rebase)
    3. 둘 중 하나를 포기 (어느 쪽 작업을 버릴지)
- > 내 답변: 알아서 잘 짬뽕

## 1. 공통/교차 저장소 이슈

### 1-1. semver 태그를 한 번도 발행한 적이 없음 (protocol, ai-module 공통)

- **기획서 내용**: `01_protocol.md` 1절/8절 — "workspace/ai-module은 protocol을 git 의존성(태그 버전)으로 참조", "스키마 변경 시 semver 태그 발행". `04_ai-module.md` 5절 — "workspace 통합 마일스톤마다 태그 필수".
- **실제 코드 상태**: `protocol`, `ai-module` 둘 다 `git tag` 결과가 **0개**. 대신 `ai-module/package.json`은 `"@speaki-e/protocol": "file:../protocol"`(로컬 경로 참조), `workspace/package.json`은 `"@speaki-e/protocol": "github:...#4244922..."`(커밋 SHA 고정, 그것도 이후 버그수정이 반영 안 된 구버전)로 참조 중.
- **왜 문제인지**: "어떤 조합이 실제로 같이 동작 검증됐는지"를 태그로 추적한다는 협업 규칙이 처음부터 지켜지지 않고 있어, 저장소 간 버전 정합성을 아무도 보증할 수 없는 상태입니다.
- > 내 답변: 음.. 이게 협업 규칙이 코드에 git tag 박는건데, 이게 클린코드 지향하는 우리 프로젝트랑 충돌만 안나면 git tag 박는걸로 다시 작성해주면 될듯

### 1-2. ai-module이 두 벌 존재 (원본 저장소 vs workspace 안에 복사본) — 이미 갈라지기 시작함

- **기획서 내용**: ai-module은 독립 저장소로 개발되고 workspace가 이를 "태그 버전"으로 설치해 쓰는 구조여야 함.
- **실제 코드 상태**: `workspace/packages/ai-module/`에 ai-module 소스가 **사람이 손으로 복사(vendoring)**된 채 커밋되어 있음. 원본(`ai-module/`)과 비교하면 이미 import 경로, 일부 주석이 갈라졌고(특히 캐노니컬 쪽이 `@speaki-e/protocol/src/index.js`라는 잘못된 경로를 참조), 앞으로 원본이 바뀌어도 자동 반영되지 않습니다.
- **왜 문제인지**: 두 사본 중 어느 게 "진짜"인지 코드만 봐서는 알 수 없고, 계속 수동 동기화해야 하는데 이미 한 번 빠뜨린 흔적(주석만 구식으로 남은 부분 등)이 있습니다.
- > 내 답변: 이거 너가 알아ㅓ서 짬뽕 시켜서 정형화 해야해. 지금 모든 작업이 다 끝났기 떄문에 모노 레포 형태로 재구성해서 전체 테스트를 돌려줘야함

### 1-3. 프로젝트 현황판(마일스톤 표)이 최신 상태를 반영하지 못함

- **기획서 내용**: `프로젝트_개요.md` — M-A는 "달성 (2026-07-28)", 근거로 "314 테스트, 8개 도구"를 명시.
- **실제 코드 상태**: M-A 달성 표기 다음 날(2026-07-29) pet-app이 3D(RealityKit/usdz) → 2D(CALayer) 렌더링으로 전면 전환했습니다. 즉 M-A 달성 근거였던 렌더링 파이프라인은 지금 코드에 없고(죽은 코드로만 남음), 재검증 기록도 없습니다. 테스트 개수도 지금은 981개로 늘어 314라는 숫자가 그 시점 스냅샷일 뿐임이 드러났습니다.
- **왜 문제인지**: "M-A ✅"라는 배지만 보고 렌더링이 이미 검증됐다고 판단하면, 실제로는 폐기된 파이프라인 기준의 낡은 근거를 믿는 셈이 됩니다.
- > 내 답변: 이것도 알아서

### 1-4. `docs/` 문서가 여러 저장소에서 삭제되거나 실제 상태와 어긋남

- **실제 코드 상태**: protocol은 `docs/*.md` + `README.md` 전체(496줄)를 삭제했는데 코드 주석은 여전히 그 문서들을 참조 중입니다. workspace의 `docs/protocol-compatibility-matrix.md`는 ai-module이 "아직 코드가 전혀 없다"고 적혀 있지만 실제로는 이미 통합까지 끝났습니다. ai-module의 `TODO.md`도 "main엔 아직 코드가 없다"고 적혀 있지만 A0~A6에 workspace 통합까지 이미 병합된 상태입니다.
- **왜 문제인지**: 문서를 신뢰해 현재 상태를 판단하면 실제보다 훨씬 뒤처진 것으로 오인하게 되고, 반대로 protocol처럼 산출물 요건(docs 5종) 자체가 사라진 경우도 있습니다.
- > 내 답변: 이것도 알아서
